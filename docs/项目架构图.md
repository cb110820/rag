## 二、各层职责与源码位置

### 2.1 接入层（src/api/）

| 模块 | 端点 | 职责 |
|------|------|------|
| `app.py` | `/chat`、`/chat/resume`、`/chat/stream`、`/knowledge/*`、`/knowledge/lint`、`/skills/*`、`/health` | 主入口、对话流、知识库与技能管理、知识健康检查 |
| `auth.py` | `/auth/*` | 登录认证，租户 `status=suspended` 返回 403 |
| `threads.py` | `/threads/*` | 会话 CRUD，按 `tenant_id` 隔离 |
| `memory.py` | `/memory/facts*` | 用户记忆自助管理（列表/单查/删除） |
| `admin.py` | `/api/admin/tenants*` | 平台管理，`require_platform_admin` 守护 |
| `wiki.py` | `/wiki/*` | Wiki 页面/版本/附件/搜索 |
| `curation.py` | `/knowledge/curate`、`/knowledge/curate-all` | 手动沉淀（单篇/批量），与自动调度共用同一 service 与 per-tenant 锁；另一进程执行中返回 409 |

- 所有业务端点从登录态取 `tenant_id`，禁止从请求参数传入。
- `web/` 静态前端最后 `mount("/")`，避免吞掉 API 路由。

### 2.2 代理层（src/agents/graph.py）

- `build_agent()` 使用 `create_deep_agent()` 装配，不手写 StateGraph。
- 中间件栈：TodoListMiddleware（规划）→ FilesystemMiddleware（`CompositeBackend`：`/skills/` 只读磁盘、`/memory/` GuardedStoreBackend 护栏包装）→ SummarizationMiddleware（6000 tokens 触发压缩）→ HITL `interrupt_on`（forget_memory、write_file、edit_file 仅 `/memory/` 路径）。
- 记忆三工具只挂主代理；RAG 子代理（`subagents.py: build_rag_subagent`）声明式注册、只读，经内置 `task` 工具委托。
- 身份注入：`(tenant_id, user_id)` 经 `context_schema` 随图执行传递，工具从 `get_runtime().context` 读取。
- 技能热加载：上传后对话接口注入 `skills_metadata=None` 强制中间件重扫目录，无需重启。

### 2.3 能力层

**RAG 检索（src/rag/）**
- `pipeline.py: KnowledgeBase.search`：查询理解门控（`query_enhancer.py`，`query_understand_enabled` 默认关、超时降级直通）→ 混合召回（向量 + BM25）→ RRF 融合 → 实体注入（`entity_index.py`，`entity_search_enabled` 默认开，命中 entity 页结论直接并入结果）→ bge-reranker-v2-m3 重排 → CRAG 自我纠正（首轮最高分 < `crag_threshold` 时用增强查询重试）。
- `tools.py: retrieve_knowledge`：检索能力封装为 LangChain `@tool`，租户从 runtime context 注入。
- `knowledge_contract.py`：Wiki 与 RAG 的唯一契约层——路径规则、镜像操作、刷新通知的唯一所有权入口；Wiki 页面变更自动镜像到 `KNOWLEDGE_DIR/<tenant_id>/` 并触发增量索引。
- 知识库上传经契约层路径穿越防护与保留前缀守卫，禁止写入 `wiki/` 子目录。

**记忆系统（src/memory/）**
- 两类载体：画像记忆（`/memory/AGENTS.md`，长期稳定身份偏好，文件式编辑）+ 事实记忆（独立条目，向量召回、可单删、可设 TTL）。
- 三条写入路径（模型调工具 / 模型写 `/memory/` 文件 / LangMem 后台反思）统一过护栏：`scan_secret` 凭据扫描 → 长度校验 → 双层配额（`min(全局 memory_fact_max_items, 租户 max_facts)`）→ 语义去重（bge-m3 向量 / hash·none Jaccard，阈值 0.9）。
- 去重命中原地更新，经 value 冗余的绝对过期时刻保留原 TTL（langgraph 1.2.x 的 `Item` 不暴露 `expires_at` 列）。
- 召回低于 `memory_recall_min_score`（0.2）视为噪声丢弃；`forget_memory` 走 HITL 审批。
- 反思（`reflection.py`）：`/chat` 系列端点正常结束后异步调度，LangMem 只提取不碰 Store，候选逐条经 `_save_memory` 护栏落库；同人并发去重，失败仅记日志；提取模型强制 `streaming=False`。
- 详见 `docs/memory_production_deploy_checklist.md`。

**Wiki + Skills**
- Wiki：双表 append-only 版本设计，FTS5 三元组索引（触发器同步，不可用时降级 LIKE，Postgres 用 pg_trgm GIN）；一致性修复入口 `rebuild_wiki_mirrors`（以 DB 为准重写镜像）。
- Skills：`skills/manager.py` 三级校验（浏览器快检 → 服务端无盘预检 → 正式上传复核）；全局/租户双层可见性；管理接口仅 `platform_admin`。

**知识沉淀（src/curation/，LLM 自动知识化层）**
- 上传主链路旁路：`/knowledge/upload` 落盘后 fire-and-forget 调度（`scheduler.py`），LLM 超时/失败只记日志 + 写 log 页，绝不阻断上传或返回错误。
- `service.py: curate_document`：LLM 提取先行（失败不留半成品）→ upsert `doc-*` 摘要页 / `entity-*` 实体页 / `index`/`log` 系统页（作者固定 `author_id="system"`）→ 契约层镜像物化与索引刷新；新旧结论冲突只追加「矛盾待裁决」区块（`contradiction:open`），不覆盖旧结论，交人工裁决。
- `llm.py` 只做结构化提取（模型可注入、JSON 容错、`streaming=False`）；`markdown.py` 渲染纯函数；新页写入前过 `wiki_schema.py` 严格校验与 `scan_secret` 凭据扫描。
- 多副本安全：同租户串行 = 进程内 `asyncio.Lock` + Postgres advisory lock（`database.try_named_lock`，sqlite 单机退化直通）；跨进程任务去重 = `wiki_curation_tasks` 槽位表（`UNIQUE(tenant_id, source_id)` + lease 过期回收崩溃残留），另一进程执行中时手动端点返回 409、自动调度静默跳过。
- `lint.py`（`GET /knowledge/lint`）：扫描孤儿/缺失镜像、frontmatter 违例、过期/未生效、空正文、未裁决矛盾；镜像与索引均为可重建派生数据。

### 2.4 持久化层（src/persistence/database.py）

一个文件三种存储角色，SQLite（WAL + busy_timeout=5s）/ Postgres 双后端：

| 角色 | 内容 | 说明 |
|------|------|------|
| 业务表 | tenants / users / threads / wiki / knowledge_files / skills / wiki_curation_tasks（沉淀槽位） | 租户 `max_facts` 等配额列在 save 路径生效；槽位表 `UNIQUE(tenant_id, source_id)` + lease 过期回收 |
| Store | 记忆 namespace `("tenant", tid, "user_facts"\|"user_memory", uid)` + 向量索引 | `omit_expired=True`；`refresh_on_read=False` |
| Checkpointer | 对话状态 + HITL 中断态 | 重启后审批与对话可恢复 |
| TTL Sweeper | 每 `ttl_sweep_interval_minutes`（60）物理清除过期记忆 | 必须保持 >0 |

- 已注册秒级 datetime 适配器，修复 langgraph 默认适配器导致带时区时间戳与 `CURRENT_TIMESTAMP` 词法比较失效的 TTL bug。
- 记忆 Store 操作经 tenacity 重试，覆盖 `sqlite3.Error` / `psycopg.OperationalError` / 超时。

### 2.5 外部依赖

- **DashScope**：qwen-plus 主模型 + LangMem 反思提取模型；账户欠费/限流会直接表现为 Agent 执行失败，排查时优先看账户状态。
- **本地模型**：bge-m3（嵌入，懒加载；memory 侧三态 bge-m3/hash/none）、bge-reranker-v2-m3（重排，不可用退化为直通）。

## 三、/chat 请求主链路（流式）

```
浏览器前端      /chat 端点         主代理循环             SSE 响应
(SSE 流式) ──► (认证·租户注入) ──► (工具·RAG 委托) ──► (+ 后台反思调度)
                                        │
              HITL 敏感工具触发 ──► 挂起检查点 ──► 前端审批卡片
                                        │
              /chat/resume 提交决策 ──► 从断点继续（支持多工具连续挂起）
```

- **来源引用穿透**：子代理内部工具事件无法冒泡到 SSE，RAG 来源经 contextvar 注册回调 + 线程安全队列传到 `/chat/stream` 响应；非流式 `/chat` 同样返回结构化 citations。
- **审批恢复**：HITL 中断状态随检查点持久化（sqlite → `AsyncSqliteSaver` / postgres → `AsyncPostgresSaver`），`/chat/resume` 与主对话流解耦，重启可恢复。
- **反思调度**：仅正常结束（非挂起）时触发；挂起恢复后完成才调度。
